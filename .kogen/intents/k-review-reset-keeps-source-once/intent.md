# Reset a refused review request without duplicates

Slug: k-review-reset-keeps-source-once
Model: .kogen/intents/k-review-reset-keeps-source-once/model.qnt invariants=NoUnreadApproval,ReadStaysRead,UndeliveredUnread,HandoffBounded seed=7 samples=200 steps=30
Acceptance:

Today, if `Env.Request` refuses a request of the native reviewer (`review.Independent`) because it does not fit the request ceiling, the review stops. The refusal is the `*sys.Error` `candidate/context_budget_exceeded`, returned before anything is sent. Two callers refuse this way: kogen-build's working-window reset when its reset window still does not fit (it keeps the mandatory catalog and the newest batch of the same source), and `provider.Client.Respond` for an Env without a working window, such as `cmd/kogen-review` or a saved-candidate harness. After this change the reviewer handles that refusal. It resets its own working context to the unchanged mandatory opening plus one bounded handoff, archives the replaced conversation as a custody record, keeps every read that reached the model counted, and sends the request again once. In the request after the reset, each source part and each reference appears once. That request fits whenever the mandatory material alone fits. Mandatory material that does not fit still ends the review with the Env's own refusal, unchanged. No limit is raised, lowered or clipped.

Boundaries. The reviewer still hands its whole conversation to `Env.Request` first, exactly as today. It does not measure or reset before that call. A request the Env accepts, including one the caller reduced with its own working-window reset (kogen-build `build/context.go`, outside this repository), is unchanged. The previous attempt reset the conversation inside the reviewer before `Env.Request`. That preempted kogen-build's reset, and delivery's consumer gate refused it because kogen-build's consumer tests broke (`TestKReviewRetry2ForcedReset`, `TestLargeSourceIsDeliveredAsPinnedPartsAndMustBeReadBeforeApproval`, `TestTheReviewAndItsResetsCarryOnlyTheFrozenCallerDiagnostic`, `TestKReviewVerdictStrandPinnedResume` and the others of that gate). Do not do this. The external reviewer (`External`), verdict rules, allowances, the twelve-request budget, the reviewer instructions and the tool definitions are unchanged. A provider rejection after sending (`provider/context_too_long`) is not a trigger.

Settled contract (package `review`; no field of `Env`, `Request`, `Input` or `Result` is removed or renamed):

1. Trigger. In `converse`, `env.Request` returns an error `e` for which `sys.AsError(e)` gives Class `candidate` and Reason `context_budget_exceeded`. Any other error is returned as today.
2. Window. W is `r.sess.Input` exactly as passed in the refused request. The opening O is the leading items of W that are messages with `role` `user`. It stops before the first handoff message: a user message whose string content starts with `Kogen review working-context reset\n`. A model item is an item whose `type` is `function_call` or `reasoning`, or whose `role` is `assistant`. The delivered prefix D is W up to and including its last model item, or O when W has no model item. The pending items P are the rest of W after D.
3. Feedback F. These are Kogen's newest messages that had not reached the model, in order, taken from P. A `function_call_output` whose `call_id` belongs to a `submit_review` `function_call` of W, with a string `output`, becomes `{"role":"user","content":output}`. A user message with string content becomes `{"role":"user","content":content}`, unless it is the budget notice or a handoff. No other item of P is carried: read, shell and other tool outputs, and images.
4. Measure. The bytes of an input are `tools.Measure((&provider.Client{}).Body(provider.Request{Role: core.ProviderRole(r.sess.Role), Instructions: ReviewerInstructions(), Input: input, Tools: r.tools, ToolChoice: force}), core.ProviderRole(r.sess.Role))`. It fits when `Measurement.Fits`. `force` is the request's `ForceTool`, and the limit is `Measurement.InputBudgetBytes` (524288 bytes for `chatgpt` roles).
5. Mandatory material. M is the input O + F, plus the budget notice when the request is over the working budget. If M does not fit, return the Env's refusal `e` unchanged. Write no archive, emit no event and leave the session unchanged (this is today's behavior).
6. Custody record. With `k = len(Session.Windows)+1`, the file is `fmt.Sprintf("review-%d-window-%d.json", in.Number, k)`. Write it with `env.Write(file, map[string]any{"input": W})`. Its sha256 is `core.HashHex` of `core.EncodeJSON(map[string]any{"input": W})`. Append `{file, sha256}` to a new Session field `Windows` (JSON `"windows": [{"file":...,"sha256":...}]`, omitempty).
7. Read state. Before replacing W, set a new Session field `ResetUnread` (JSON `"reset_unread"`, omitempty) to `env.Unread(D)`. When `Windows` was already non-empty before this reset, keep only the parts also in the previous `ResetUnread`, in `env.Unread`'s order. The effective unread parts of an input are `env.Unread(input)`. Once `Windows` is non-empty, only those also in `ResetUnread` count, in `env.Unread`'s order. Both unread checks of `validate` (changes and approve) use the effective list and keep their current texts. A read whose output never reached the model stays unread, and a read part is never unread again.
8. Handoff H. One message `{"role":"user","content": "Kogen review working-context reset\n" + string(core.EncodeJSON(map[string]any{"version":1,"review":in.Number,"window":{"file":file,"sha256":sha},"unread_parts":len(ResetUnread),"note":N}))}`. N is exactly: `Kogen reset this review's working context because the next request did not fit the request ceiling. The earlier conversation is archived in custody (window) and is not repeated. The opening messages above are complete and unchanged: the authority, and the candidate source or its pinned catalog. Pinned parts whose reads already reached you stay counted for verdict validation; unread_parts is how many remain unread: read them with read_file. Tool results and images of the archived conversation are not repeated: run again what you still need. Any messages after this one are Kogen's newest messages of the archived conversation, which had not reached you yet.` H never carries source text, tool outputs, catalog entries or earlier custody records.
9. Post-reset input. Use O + H + F (plus the budget notice when due) if it fits. Otherwise use O + F (plus the notice), which fits because M fits. This becomes `r.sess.Input`. Checkpoint it (`route.StageReview`) with `Windows` and `ResetUnread`. Then call `env.Request` once more with the same `ForceTool`, without incrementing `Requests`, with a `Retain` that encodes the updated session and with the same `Prefill`. If that call returns any error, `converse` returns it. There is no second reset for the same request.
10. Measurement record. Before the second call, call `env.Event({"event":"review_window_reset","review":n,"window":file,"trigger":T,"bytes_before":B,"bytes_after":A,"mandatory_bytes":Mb,"handoff_bytes":A-Mb,"ceiling":limit})`. B, A and Mb are the bytes of W, the post-reset input and M. T is the `name` of the `function_call` whose `call_id` matches W's last item when that item is a `function_call_output`. T is `feedback` when the last item is a user message, and otherwise the item's `type`. Also call `env.Progress(fmt.Sprintf("kogen: review %d: working-context reset %d -> %d bytes (mandatory %d, handoff %d; ceiling %d); archived %s", n, B, A, Mb, A-Mb, limit, file))`.
11. Persistence. `Windows` and `ResetUnread` travel with every checkpoint and resume, and through the Session reconstructions in `retry` and `evaluate`. A session that never reset encodes exactly as today. Update the README `review` bullet, the `Env.Request` comment in `contract.go` and `contract/README.md` (new pinned item). They should say that the caller's working window stays the caller's and the native reviewer resets its own conversation only after a ceiling refusal.

Consumers: kogen-build's resets, prefill, deferrals and progress lines still run first and are unchanged, so its consumer tests keep passing. If a consumer test pins a review stop on `candidate/context_budget_exceeded` although that review's mandatory material fits, the stop is deliberately replaced by the reset. Report it as a `consumer-first:` line.

The acceptance step embeds a standalone Go program, which it writes to `zz-reset-driver/main.go` of a disposable copy of the checkout and runs with `go run ./zz-reset-driver <case> <output>`. The program uses only the public API of `review` and its pinned dependencies. It has its own scripted Env, which refuses, like the provider client, every request over the ceiling, and a temporary Git candidate. Do not add a top-level `zz-reset-driver` directory.

## Decisions
- The reviewer resets only after the Env refuses a request with candidate/context_budget_exceeded; the caller's own working-window reset still runs first and is unchanged, as the delivery retry requires of the consumer tests (source: request)
- The request after a reset is the mandatory opening, one bounded handoff and Kogen's newest undelivered feedback; earlier exchanges, tool outputs, model observations and earlier custody references are not carried (source: request)
- Each source part and each reference appears once after a reset; the replaced conversation is kept as a custody record outside the request (source: request)
- Reads that reached the reviewer stay counted across resets; an unread part still blocks approval (source: request)
- Mandatory material that cannot fit still refuses before anything is sent, with the Env's own refusal; no limit is raised or clipped (source: request)
- A conversation that never outgrows the ceiling keeps its exact request bytes (source: request)

- Addressed: Need (preserve the full source, custody records and authority). O is kept verbatim (items 2 and 9). Each replaced window is archived with SHA-256 in `Session.windows` and named once in the handoff (items 6 and 8).
- Addressed: Need (fits whenever mandatory material alone fits; no limit raised or clipped): items 5 and 9; scenarios tight and mandatory.
- Addressed: Need (nothing read forgotten so that an unread part is approved): item 7; scenario pinned and the Quint invariants.
- Addressed: Synthetic acceptance. Bullet 1 is scenario points (resets after read_file, shell and a rejected submit_review). ## Tests
- A refused over-ceiling native request becomes O + H (+ F) after a read, a shell result and a rejected verdict, with each source part and reference once and under the ceiling: acceptance case points; add `contract/reset_test.go` with a fake Env that refuses over the ceiling and asserts the post-reset input shape (integration)
- A reset right after a reset does not grow the handoff, and rejected-verdict feedback is carried once while undelivered: acceptance case points; same contract test (integration)
- Each reset writes the custody record whose SHA-256 is the refused conversation's, appends it to Session windows and records the review_window_reset event and progress line: acceptance case points; contract test asserts file, event and progress (integration)
- Reads that reached the model stay read after a reset, an undelivered read stays unread, and an unread part blocks approval: acceptance case pinned; contract test of the rejection text after a reset (integration)
- When only the mandatory material fits, the post-reset request is O + F without a handoff: acceptance case tight (integration)
- Mandatory material over the ceiling ends the review with the Env's own refusal and writes no record: acceptance case mandatory (regression)
- A post-reset request the Env refuses again ends the review with that refusal, without a second reset: contract test (integration)
- A request the Env accepts is sent unchanged: acceptance case fits plus existing `TestIndependentReviewApprovesTheGreenPass` and the other contract tests (existing)
- Session windows and reset_unread encode, decode and survive retry and repair reconstructions, while sessions that never reset keep their exact bytes: extend `contract/formats_test.go` (unit)
