# Return listed requirements in repair feedback

Slug: review-repair-feedback-lists-requirements
Model: not applicable — the change only appends text computed from an existing list to one feedback string; it adds no state, transition or interacting rule
Acceptance:
- .kogen/intents/review-repair-feedback-lists-requirements/acceptance.feature
- features/steps/review-repair-feedback-lists-requirements__steps.js

An approval that Kogen accepted binds every later approval of the same review: each of its requirements must appear again, matched by its text with whitespace collapsed and case ignored (`missing` in `review/independent.go`). The feedback that returns the reviewer to another round after the candidate changed (the reviewer's own repair changed the tree, or final verification of its repair failed) never repeats that list, so the reviewer rewords or drops entries from memory, the second refusal ends the review and a green Build can end as `candidate/review_invalid`.

Observed in an AoR climb (cell rails-ft-data-export-and-import): the Build ended `failed rails-ft-data-export-and-import: review_invalid` after a green pass 2. Round 2 submitted an approval with 8 requirements; Kogen accepted it and returned the reviewer to round 3 with the progress line `kogen: review 1: the candidate changed after its contents were delivered (app/models/zip_file/reader.rb, test/models/zip_file_test.rb); returning the changes to the reviewer`. Round 3 reworded five requirements, for example `Admin exports whole account as one zip, emailed link; members get 403` for `Admin (owner/admin) exports whole account as one zip from settings, emailed link; members get 403`, and was refused with problems each ending `was listed by an earlier submission of this review and is missing: keep every requirement in requirements, with evidence observed on the current tree` (the problem text begins `was listed by an earlier submission of this review and is missing`). Round 4 left out `Import runs in one transaction with cleanup of uploaded blobs on failure`; the review event recorded reason `rejected_verdict_exhausted` and the Build stopped with `candidate/review_invalid: the reviewer did not return a valid verdict; edits are left in place`. The review rule (RequirementsRule) says only `requirement (quoted from the Intent)`, and the feedback built after `deliverySection` never says that the earlier list binds the next approval. `validate` in `review/independent.go` appends to `r.sess.Listed` the texts of accepted submissions.

After this change both repair-round feedbacks of `evaluate` carry the binding list, on the native and the external route (the external executor receives the same text as `lastUserContent` of the native conversation). One helper builds the block from `r.sess.Listed`, the stored texts of the requirements of accepted submissions in the order first listed, the same texts `missing` quotes. `evaluate` appends it after the existing text in the green final pass branch (`The new tree passed checks but has not been reviewed. Inspect these changes and submit_review for the current contents; do not restart the whole critique.`) and in the failed final verification branch (the paragraph that begins `Final verification of your repairs failed.` plus `env.Feedback(final, SubmitReviewTool)`). When `Listed` is empty nothing is appended.

The block is the existing feedback text, then a blank line (the two characters `\n\n`), then the header line `Requirements already listed in this review (your next approval must list each of them, with this text and with evidence observed on the current tree):`, then one line per listed requirement in listed order, each `- ` followed by the requirement text with each run of whitespace (including line breaks) replaced by one space and leading and trailing whitespace removed. There is no newline after the last line. For example a listed requirement `R1\n  second   line` (a line break and runs of spaces inside the JSON string) is shown as the line `- R1 second line`.

Nothing else changes: the problem texts and the refusal feedback (the `Not a valid verdict:` and `invalid verdict:` prefixes and their problems), `missing`, `identity`, `Listed`, the allowance counts (one rejected verdict is still allowed per review), the review events, the stop text, the existing feedback text before the block (including the byte-identical diff section and the progress line that names the changed paths), the submit_review schema, RequirementsRule and every decision. No new configuration. The caller-resumed blocked-review feedback (`retry`, `The caller explicitly resumed this blocked Build.`) is not changed. The refused-verdict progress lines of the review and what the Build prints for review_invalid are out of scope.

The existing expectations in contract/independent_test.go (`TestIndependentApprovalOfAnUnverifiedTreeIsVerifiedFirst`) and contract/reset_test.go (`Final verification of your repairs failed` counted once) keep passing unchanged: they run without accepted requirements, so no block is appended there. Another existing test that lists a requirement and compares the whole repair feedback may be updated only to append the block. The Build's own tests change the candidate with `writeFile(t, filepath.Join(in.Candidate.Root, "app.txt"), otherText)` and give the final pass as `verify.Pass{N: 2, Clean: true, Green: true, Tree: otherTree}` (the red one with `Green` false and `Failing: []string{"check:lint"}`, followed by a green `N: 3` pass); they run with `go test ./contract -run` and the new tests' name pattern.

## Decisions
- One helper on the review run builds the block from `r.sess.Listed`, and `evaluate` appends its result to the feedback in both repair branches after the existing text; an empty `Listed` appends nothing (decision: D1, round 1) (constraint: the block is `\n\n`, the header line, then one `- <text>` line per requirement in listed order with no trailing newline) (evidence: review/independent.go) (source: request)
- The requirement text in a block line has each run of whitespace, line breaks included, replaced by one space and the ends trimmed; case is kept (decision: D2, round 1) (constraint: the text is the stored text `missing` quotes, so repeating a line verbatim never meets the `was listed by an earlier submission` refusal) (evidence: review/independent.go) (source: request)
- The native and external routes share the feedback text: the external executor receives `lastUserContent(r.sess.Input)`, so no external-only code is added (decision: D3, round 1) (evidence: review/external.go) (source: request)
- The caller-resumed blocked-review feedback, the refusal feedback, `missing`, the allowance counts, events, stop text and schema are not changed (decision: D4, round 1) (evidence: review/independent.go) (source: request)
- The Build adds focused model-free Go tests in contract/independent_test.go next to `TestIndependentApprovalOfAnUnverifiedTreeIsVerifiedFirst` and contract/external_test.go next to `TestExternalReviewRequirementsSkipTheProbeCheck`, using `newReview`, `submitReview`, `fakeExecutor`, `structured` and `h.verifies`; the acceptance driver runs its own generated contract test in a disposable copy, so it names no test the Build must write (decision: D5, round 1) (evidence: contract/independent_test.go; contract/external_test.go; contract/helper_test.go) (source: request)
