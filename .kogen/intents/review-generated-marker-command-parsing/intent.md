# Drop sentence punctuation from a marker command

Slug: review-generated-marker-command-parsing
Model: not applicable — generatedMarkerOf is a pure text transformation of one marker line, with no state
Acceptance:
- .kogen/intents/review-generated-marker-command-parsing/acceptance.feature
- features/steps/review-generated-marker-command-parsing__steps.js

This feature makes `generatedMarkerOf` in `review/generated.go` return the regenerating command of a `Code generated by <command> DO NOT EDIT.` marker without the optional sentence-ending punctuation (a single `.` or `;`) that stands directly before `DO NOT EDIT.`, whatever whitespace separates that punctuation from `DO NOT EDIT.`, while keeping punctuation that belongs inside the command (for example a flag value such as `-version=1.5`). Today a period followed by more than one space or other whitespace before `DO NOT EDIT.` stays in the returned command, so the later `sh -c` regeneration runs a command ending in a period and the generated content stays in the review prompt.

Out of scope and unchanged: where the marker may stand (the first five lines), the large-file size limit, valid UTF-8 and NUL checks, and regeneration behavior. Existing results for command, line and validity stay as they are.

- The separator between the optional `.` or `;` and `DO NOT EDIT.` is one or more whitespace characters instead of exactly one space; at most one trailing `.` or `;` is dropped, and every other character of the command, including inner periods, is kept. ## Source comparison
- Request item 1 (a command followed by a period before `DO NOT EDIT.` returns the command without that period): addressed for the period followed by any whitespace run; scenario "A period before DO NOT EDIT is not part of the command".
- Request item 2 (punctuation inside the command is preserved, e.g. a flag value with a period): addressed; scenarios "Punctuation inside the command is kept" and "Dots inside a command with no sentence period are kept".
- Request item 3 (existing parsing results unchanged): addressed; scenarios for the semicolon, the single-space period, no separator, a marker past line 5 and an empty command.
- Out of scope as the request states: marker placement rules, generated-file size limits, regeneration behavior.
