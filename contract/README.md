# Contract suite

This package is the contract of kogen-review with its consumer, kogen-build. It pins exactly what kogen-build uses: the exported API it calls, the behaviours it relies on and the formats the reviewer writes into a Build's checkpoints and run folder. It runs in kogen-review's own fast gate, `go test ./...`, so an interface change fails here first, without the kogen-build repository.

An intended interface change edits this contract together with paired consumer items: the kogen-build tests named in each test's comment.

Run it with the rest of the module, or alone:

```sh
go test -race -count=1 ./contract/...
```

## What it is made of

- The cases are copied and adapted from kogen-build's own tests of the review, at `b47cde70dcdf4fea58f2043b31619b07e8bdc9da` (`build/review_test.go`, `review_lineup_test.go`, `review_parts_build_test.go`, `review_prefill_test.go`, `k_revod_gate_test.go`, `k_reviewretry2_test.go`, `legacy_test.go`, `state_golden_test.go`), and from its call sites: `build/host.go` (`delegate{review.Independent{}}`), `build/executor_external.go` (`delegate{review.NewExternal(ex, desc, max)}`), `build/hooks.go` (`review.File`), `build/review_retry.go` (`review.DecodeSession`) and `build/legacy.go` (`review.Session`, `Submitted`, `Verdict`, `Session.Encode`).
- No Build is involved. A review's `Input` is a saved candidate in a `t.TempDir()` Git checkout (a start commit and the candidate in the checkout) with a run folder; the review makes its material and reads the candidate's trees from it. Its `Env` is a fake that scripts the model's answers (`provider.Response` values returned by `Request`) and the verification passes, and records what the reviewer asks of its caller. The external executor is a fake `executor.Executor` whose sessions return scripted structured verdicts. `saved_candidate_test.go` is the saved-candidate harness: a real Git checkout whose HEAD is the saved candidate commit, with a version 4 checkpoint (`.kogen/local/runs/<id>/checkpoint.json`, an envelope and a state the test declares itself, written with kogen-build's persisted keys and read back through review's own types) in its run folder; the review's `Input` is built from that checkpoint read back from disk, the native reviewer reads the checkout with its real `read_file` tool, the `Env` is the harness's own, and the resume uses the checkpoint of the saved state's continuation.
- `TestMain` strips `GIT_*` and `KOGEN_*`, sets a HOME of its own, `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`, and calls `durable.SkipSyncInTests`.
- The suite imports only the standard library, `review`, kogen-executor `core` and `executor`, kogen-coordinator `project`, `route` and `durable`, kogen-verification `verify` and kogen-loop `provider`, `sys` and `tools`. No model runs and nothing reaches the network: there is no provider server at all, no fixed port and no shared path. It does not read kogen-review's own sources or kogen-build's goldens, has no `t.Skip`, no sleep and no build constraint, and passes with `-count=1`, `-trimpath` and `-race`.

## Behaviours and formats pinned

Each item is asserted so that changing it fails the suite.

- `api-signatures`, `api_test.go` (compile-time): `review.Independent{}` and `review.External{}` are `review.Reviewer`s; `NewExternal` is `func(executor.Executor, executor.Descriptor, int) review.External`; the `Review` and `Resume` methods of both, `func(context.Context, review.Input, review.Env) (review.Result, error)`; `File func(int) string`; `DecodeSession func(json.RawMessage) (review.Session, error)`; `Session.Encode`; `InvalidError func() *sys.Error`; `InvalidRecord func(int) core.ReviewRecord`; `Validate func(review.Input, review.Env, map[string]any, []any) (*review.Verdict, []string, error)`; `ToolNames []string`; `ReviewerInstructions`, `ReviewerToolDefinitions`, `SubmitReviewTool`, `LimitRaises`, `RequirementsRule`; `MaterialOf func(review.Input) (review.MaterialSet, error)`, `MaterialPartBytes`.
- `api-fields`, `api_test.go` (compile-time): the fields of `Session`, `Submitted`, `Verdict`, `Part` and `Material` that kogen-build sets or reads, and every field of the narrow contract kogen-build adapts its state to (`Input`, `Candidate`, `Intent`, `Evidence`, `Commands`, `Tools`, `Checkpoint`, `Run`, `Result`, `Invalid`, `Request`, `Done`) and of the review material the Build keeps in its review working window (`MaterialSet`, `MaterialSegment`, `MaterialHunkRange`, `MaterialFileText`), with their types; the fake satisfies `review.Env`.
- `review-file`, `TestReviewRecordFileName`: a review's record is `review-<n>.json`.
- `tool-names`, `TestReviewerToolNames`: the reviewer's native tools are read_file, view_image, list_files, search_text, write_file and shell, in that order.
- `invalid-stop`, `TestInvalidErrorIsTheReviewInvalidStop`: `candidate/review_invalid`, its detail and exit 1.
- `session-json`, `TestSessionEncodesItsCheckpointBytes`: the exact bytes of a session in `continuation.review`: key names and order, omitted empty fields, nil lists as `[]`, no HTML escaping.
- `session-decode`, `TestDecodeSessionReadsWhatACheckpointKept`: every field round-trips, numbers stay `json.Number`, and malformed or missing state is an error.
- `reset-after-refusal`, `reset_test.go`: the caller's working window stays the caller's: the reviewer hands its whole conversation to `Env.Request` first. Only when the Env refuses it with `candidate/context_budget_exceeded` (nothing sent) does the native reviewer reset its own conversation once: the request sent again is the unchanged opening and one bounded handoff (and Kogen's newest undelivered messages), the replaced conversation is a custody record `review-<n>-window-<k>.json` with its SHA-256 in `Session.Windows`, the `review_window_reset` event and a progress line record the bytes, and `Requests` is not incremented. A second refusal, mandatory material that does not fit, and any other error end the review with the Env's own error (`TestAReviewStopsOnTheEnvsRefusalWhenItCannotBeResolvedByAReset`, `TestOnlyACeilingRefusalTriggersAReset`).
- `reset-read-state`, `reset_test.go`: a read whose output reached the model stays read after a reset, an undelivered read stays unread (`Session.ResetUnread`), and the approval text for unread parts is unchanged; undelivered rejected-verdict feedback is carried once (`TestRejectedVerdictFeedbackIsCarriedOnceAcrossResets`).
- `reset-persistence`, `TestSessionResetFieldsEncodeAndDecode`, `TestResetFieldsSurviveTheRetryReconstruction`, `TestResetFieldsSurviveTheRepairReconstruction`: `windows` and `reset_unread` follow the other session keys, round-trip, survive the retry and repair reconstructions (a reset after Kogen's repair feedback has the trigger `feedback`), and a session that never reset encodes the same bytes.
- `material-json`, `TestMaterialEvidenceJSON` and `TestExternalReviewApprovesInItsOwnSession`: the keys of `review-<n>-material.json` read through `Material` and `Part`, and the retained material's custody (0700 folder, 0600 files) and delivery.
- `validate-shape`, `TestValidateAcceptsTheVerdictShapes` (20 subtests): the accepted verdicts and the exact problem text of every shape and inner-validation failure, never disclosing submitted values; a finding's path must be a file of the checkout or of the start HEAD.
- `validate-unread`, `TestValidateRefusesAVerdictWithUnreadParts`: a native verdict needs every pinned part read, with the two problem texts.
- `independent-approve` and `review-record`, `TestIndependentReviewApprovesTheGreenPass`: the review of the number it is given, one request of the review role with the reviewer's instructions and `submit_review`, the stages review → tool → review_verify, the progress lines, the material event, `review-1.json` with model, effort, usage, verdict, findings, tree and attempts, the `review` run-log event and the approval of the pass under review.
- `independent-blocked`, `TestIndependentReviewChangesIsTheReviewBlockedStop`: a changes verdict is `candidate/review_blocked` (exit 1) with one `review: <path>:<line>: <message>` line per blocking finding, the Result carries the verdict and findings, and the verdict stays in a review_verify checkpoint.
- `independent-invalid`, `TestIndependentReviewWithoutAVerdictIsHandedToTheBuild`: one reminder that forces `submit_review`, then the Result carries the review's `Invalid` (reason `no_tool_reminder_exhausted`), its record is `review.InvalidRecord`, and the stop is `candidate/review_invalid`.
- `independent-exact-tree`, `TestIndependentApprovalOfAnUnverifiedTreeIsVerifiedFirst`: an approval of a tree that is not the green pass's is verified by the caller (`Env.Verify`), counted as one repair, the changes go back to the same reviewer with their diff, and only the approval of the verified tree binds.
- `independent-resume`, `TestIndependentResumeJudgesTheSavedVerdict`: a review_verify checkpoint's approval is judged again without a request; unreadable review state is `candidate/resume_refused`.
- `external-approve`, `TestExternalReviewApprovesInItsOwnSession`: one fresh executor session of the review role with the model, effort, run id, round cap and `submit_review` schema, the review executor state and the `executor_round` event, and the approval.
- `external-invalid`, `TestExternalReviewCorrectsAnInvalidVerdictOnce`: an invalid structured verdict is sent back once with its text; the second ends the review (`rejected_verdict_exhausted`, `candidate/review_invalid`).
- `external-resume`, `TestExternalReviewHasNoResume`: `External.Resume` is `candidate/resume_refused` with its detail.
- `reviewer-policy`, `TestReviewerPolicy`: `submit_review` and its definition, the generic tools' definitions, and the instructions carrying the limit-raise rule once (pinned by kogen-executor's contract while executor held them).
- `saved-candidate`, `TestReviewOfASavedCandidateWithoutABuild`: the native review of a candidate saved as a Git commit, with no Build attempt at all: the reviewer gets the approved Intent and the candidate's diff, reads its file with its permitted tool and approves; the Result is the verdict, findings and no repairs on the saved tree's green pass, and the checkpoint of the saved state's continuation resumes the review without a new request. The review's `Input` and that resume checkpoint come from a version 4 checkpoint read from the saved candidate's run folder, not from memory.
- `validate-requirements`, `TestValidateChecksTheRequirementsOfAVerdict`: `submit_review`'s optional `requirements`: absent or `null` is validated as before; a malformed array gives the one shape problem without disclosing a submitted value; an approval with an entry whose evidence is `none`, whose `met` is false or (native reviewer) whose probe did not run, as a `shell` call of the conversation `input` or `Session.Probes`, gives its exact problem; a changes verdict needs a blocking finding quoting each unmet requirement; the accepted verdict carries the entries.
- `validate-evidence`, `TestValidateJudgesRequirementEvidenceOnTheCurrentTree`: an approval's `acceptance` entry is judged against `Input.Evidence.Pass` (not run, another tree, no scenario cited, a cited scenario failed or not passed; a scenario that passed on the current tree needs no probe) and a native `probe` entry against its latest run (it names no file or directory of the current tree, did not succeed, ran on another tree), each with its exact problem; `test` entries and the entries of a changes verdict are checked as before.
- `session-probes`, `session-probe-runs` and `review-requirements`, `TestIndependentReviewRecordsItsProbesAndRequirements`: the native review records the command of each `shell` call in `Session.Probes` and its command, exit status and tree in `Session.ProbeRuns`, keeps them in the checkpoint and through a repair round, accepts a cited probe that ran, and writes `review-<n>.json` with `"requirements"` (`[]` without any).
- `session-listed`, `TestIndependentReviewJudgesACitedProbeByItsLatestRun`: a cited probe whose latest run was on an older tree is refused naming both trees, running it again establishes the requirement, and an approval that drops a requirement an earlier submission listed (`Session.Listed`), with `requirements` absent or the entry missing, is refused.
- `external-requirements`, `TestExternalReviewRequirementsSkipTheProbeCheck`: the external reviewer's approval citing a probe is accepted without the probe-ran check, one citing acceptance in a pass that records it not run and one with evidence `none` are sent back with its problem in the feedback text.
- `requirements-rule`, `review.TestReviewerBatchPromptBytesAndUnchangedSchema` and `review.TestExternalReviewTaskCarriesTheRequirementsRule`: the reviewer's instructions and the external review task carry `RequirementsRule`; `submit_review` has the `requirements` parameter (`defs_golden.json`).

`review.Prompt`, `review.PartsRule` and `review.OnDemandRule` are exported but no consumer uses them: the on_demand review mode they serve was removed from kogen-build (`dfa857f`, `b47cde7`).

The native session checkpoint optionally retains `repair_rounds`, `failure_identities` (the
sorted set of stage-qualified final failures), and `failure_streak`. Missing fields default to
zero for older checkpoints. These values survive retained conversations and blocked-review resume;
resume's fresh verification does not itself consume a repair round.
